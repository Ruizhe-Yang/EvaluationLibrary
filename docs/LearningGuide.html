EvaluationLibrary 0.4.0 guide

Overview

EvaluationLibrary 0.4.0 observes signals and organizes qualified evidence. Its ten first-level packages separate signal operations, statistics, event/response analysis, requirements, comparison, frequency analysis, results and shared utilities. It neither changes a host model nor performs automatic hazard reasoning.

GettingStarted

Load the library and run MultiSignalAssessment with its declared experiment. For a host, connect observed signals to SignalAssessment.u, declare each channel interpretation and bounds, then connect the complete y array to ConsoleWriter.u. Use EventAssessment for separately observed requests and actual feedback. Configure identities and units once, at producers. No result-field equations or output relay blocks are needed.

Conventions

Windows are half open. Continuous duration statistics and event inequalities differ from uniform-grid statistics and sampled extrema. Angle wrapping applies only to radian angle differences. DataStatus describes qualification; Verdict describes a requirement decision. No available number or safety pass is inferred from an unavailable numeric placeholder. INVALID dominates witnessed violations in overall interpretation, but the violation witness is retained.

Limitations

Finite samples are not strict continuous extrema; finite candidates are not global worst-case proofs or probabilities. Levels 0/1/2 are engineering categories. Event queues are bounded and overflow invalidates evidence. Only the first externally gated window is accepted by retained gate-based metrics. A file output error may stop a simulation without changing the computed verdict. OpenModelica 1.27.1 command-line execution was tested; OpenModelica 1.25.x and MWorks runtime execution remain unverified.
